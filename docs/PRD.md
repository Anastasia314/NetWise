## 1. Обзор и Цель (Overview & Purpose)

**Networking Bot** — это Telegram-бот на Python, предназначенный для упрощения и повышения эффективности нетворкинга на конференциях, митапах и других мероприятиях.

**Проблема:** В больших чатах мероприятий (сотни и тысячи участников) сложно найти релевантных людей для общения. Поиск вручную отнимает много времени, а сообщения с представлением себя быстро теряются в общем потоке.

**Решение:** Бот проактивно вовлекает новых участников чата, предлагает им создать короткий профиль с тегами интересов и помогает находить других участников по совпадающим тегам. Это превращает хаотичный чат в структурированную базу контактов для целенаправленного нетворкинга.

## 2. Цели и Задачи (Goals & Objectives)

### Цели для пользователя:
*   Быстро находить релевантных людей для делового общения.
*   Экономить время на поиске контактов во время и после мероприятия.
*   Быть «видимым» для других заинтересованных участников.

### Цели для организатора мероприятия:
*   Повысить ценность участия в мероприятии за счет качественного нетворкинга.
*   Увеличить вовлеченность и удовлетворенность участников.
*   Получить современный и технологичный инструмент для сообщества.

## 3. Целевая аудитория (Target Audience)

*   **Участники конференций, выставок, митапов:** Специалисты из разных областей (IT, маркетинг, продажи, HR и т.д.), которые хотят найти клиентов, партнеров, работодателей или просто обменяться опытом.
*   **Организаторы мероприятий:** Компании и частные лица, которые хотят предоставить своим участникам дополнительную ценность.

### Персона (Пример)

*   **Алексей, Инфлюенсер:** Пришел на конференцию по маркетингу. Хочет найти бренды для сотрудничества. Ему важно быстро отфильтровать менеджеров брендов, которые работают по модели CPA и заинтересованы в его тематике (Lifestyle).
*   **Мария, Бренд-менеджер:** Представляет косметический бренд. Ищет лайфстайл-инфлюенсеров из США для рекламной кампании. У нее нет времени просматривать сотни сообщений в чате.

## 4. Пользовательские сценарии и Юзер-флоу (User Stories & Flow)

### Сценарий 1: Первичная настройка профиля

1.  **Пользователь (Юзер)** добавляется в основной чат мероприятия.
2.  **Система (Бот)** автоматически обнаруживает нового участника.
3.  **Бот** публикует приветственное сообщение **в общем чате**, упоминая нового пользователя и предлагая начать создание профиля через inline-кнопку.
    *   ***Пример текста в общем чате:*** «Привет, [Имя Юзера]! 👋 Добро пожаловать на [Название Конференции]. Чтобы найти полезные контакты, создай свой профиль в нашем нетворкинг-боте. Нажми на кнопку ниже, чтобы начать!»
    *   ***Кнопка под сообщением:*** `[ 🚀 Создать профиль ]` *(кнопка ведет в личный чат с ботом)*
4.  **Юзер** нажимает на кнопку `🚀 Создать профиль`. Открывается личный чат с ботом.
5.  **Бот** в ЛС последовательно задает вопросы:
    *   «Как тебя зовут? (Можно использовать псевдоним)»
    *   «В какой компании ты работаешь?»
    *   «Какая у тебя должность?»
    *   «Теперь укажи 1-3 тега, которые описывают **тебя**. Например: `influencer, lifestyle, USA`. Отправь их через запятую.»
    *   «Отлично! А теперь укажи 1-3 тега, которые описывают, **кого ты ищешь**. Например: `brand, beauty, CPA`.»
6.  **Бот** показывает Юзеру превью его профиля для подтверждения.
    *   *Текст сообщения:* «Вот твой профиль:
        *   **Имя:** Алексей
        *   **Компания:** AlexBlog
        *   **Должность:** Influencer
        *   **Мои теги:** `influencer`, `lifestyle`, `USA`
        *   **Ищу:** `brand`, `beauty`, `CPA`
        Все верно?»
    *   *Кнопки:* `✅ Все верно`, `✏️ Изменить`
7.  Если **Юзер** нажимает `✅ Все верно`, **Бот** сохраняет профиль в базу данных и автоматически запускает первый поиск.
8.  Если **Юзер** нажимает `✏️ Изменить`, **Бот** предлагает выбрать, что именно изменить, и проводит по шагам редактирования.

### Сценарий 2: Поиск и взаимодействие с контактами

1.  После создания профиля (или по команде `/search`) **Бот** выполняет поиск.
2.  **Алгоритм поиска:** Бот ищет в базе других пользователей, у которых **"Мои теги"** пересекаются с **"Ищу"** тегами текущего Юзера.
3.  **Бот** присылает в ЛС подборку из 3-5 наиболее релевантных контактов в виде "карточек".
    *   *Формат карточки:*
        > **Имя:** Мария Иванова
        > **Компания:** BeautyBrand Inc.
        > **Должность:** Бренд-менеджер
        > **Теги:** `brand`, `beauty`, `e-commerce`
        >
        > `💬 Написать Марии` (кнопка, ведущая на профиль пользователя в Telegram: `tg://user?id=...`)
4.  Если найдено больше контактов, под списком отображаются кнопки для навигации: `▶️ Следующие 5`, `🔄 Новый поиск`.
5.  **Юзер** просматривает карточки и может нажать на кнопку `💬 Написать`, чтобы перейти в личный чат с выбранным человеком.

### Сценарий 3: Редактирование профиля

1.  В любой момент **Юзер** может отправить боту команду `/myprofile`.
2.  **Бот** присылает текущий профиль пользователя и кнопки `✏️ Изменить профиль` и `🗑️ Удалить профиль`.
3.  При нажатии на `✏️ Изменить профиль` бот запускает сценарий редактирования данных, аналогичный шагу 6 из Сценария 1.

## 5. Функциональные требования (Functional Requirements)

| ID     | Требование                                                                                                                                                                             | Приоритет |
| :----- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-------- |
| **FR-1** | **Обнаружение:** Бот должен отслеживать событие добавления новых пользователей в целевой групповой чат.                                                                                    | Высокий   |
| **FR-2** | **Вовлечение:** При добавлении нового пользователя, бот должен публиковать **в общем чате** приветственное сообщение с упоминанием пользователя и inline-кнопкой для перехода в ЛС с ботом. | Высокий   |
| **FR-3** | **Профиль:** Реализовать пошаговый диалог для создания профиля (Имя, Компания, Должность, Мои теги, Ищу теги).                                                                           | Высокий   |
| **FR-4** | Данные профиля (включая Telegram User ID) должны сохраняться в базе данных (например, Supabase).                                                                                      | Высокий   |
| **FR-5** | Пользователь должен иметь возможность просмотреть, отредактировать и удалить свой профиль (`/myprofile`).                                                                             | Средний   |
| **FR-6** | **Валидация:** Система должна проверять количество тегов (не более 3-х на каждый тип).                                                                                                   | Средний   |
| **FR-7** | **Поиск:** Реализовать команду `/search` для ручного запуска поиска контактов.                                                                                                         | Высокий   |
| **FR-8** | **Мэтчинг:** Алгоритм должен сопоставлять теги из поля "Ищу" одного юзера с тегами из поля "Мои теги" других.                                                                              | Высокий   |
| **FR-9** | Бот не должен показывать пользователя в результатах поиска самому себе.                                                                                                                | Высокий   |
| **FR-10**| **Отображение:** Результаты поиска должны выводиться в виде "карточек" с информацией и кнопкой для связи.                                                                               | Высокий   |
| **FR-11**| Реализовать пагинацию (разбиение на страницы) для результатов поиска, если их много.                                                                                                     | Средний   |

## 6. Нефункциональные требования (Non-Functional Requirements)

| ID      | Требование           | Описание                                                                                             |
| :------ | :------------------- | :--------------------------------------------------------------------------------------------------- |
| **NFR-1** | **Производительность** | Ответ бота на команды пользователя не должен превышать 2 секунды.                                   |
| **NFR-2** | **Надежность**         | Uptime бота должен составлять 99.5% на время проведения мероприятия.                                 |
| **NFR-3** | **Масштабируемость**   | Бот должен выдерживать одновременное добавление до 100 пользователей в чат (пиковая нагрузка).       |
| **NFR-4** | **Безопасность**       | Персональные данные пользователей должны храниться в безопасности. Не допускать утечек Telegram ID. |
| **NFR-5** | **Юзабилити**          | Интерфейс бота должен быть интуитивно понятным, с четкими инструкциями и кнопками-подсказками.      |

## 7. Что не входит в эту версию (Out of Scope)

*   Веб-интерфейс или панель администратора для организаторов.
*   Сложный алгоритм мэтчинга на основе NLP (используем простое пересечение тегов).
*   Многоязычная поддержка (первая версия только на русском языке).
*   Возможность интеграции с несколькими чатами одновременно для одного бота.
*   Монетизация (платные функции, подписки).

## 8. Метрики успеха (Success Metrics)

*   **Активация:** Процент участников чата, создавших профиль в боте (цель: > 40%).
*   **Вовлеченность:** Среднее количество запусков поиска (`/search`) на одного активного пользователя.
*   **Польза:** Количество кликов по кнопкам `💬 Написать` (косвенный показатель установленных контактов).
*   **Удержание (Retention):** Низкий процент пользователей, удаливших свой профиль или заблокировавших бота во время ивента.
*   **Качественная обратная связь:** Положительные отзывы от пользователей и организаторов мероприятия.
